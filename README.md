# كَم؟ KAM — v2.1.1

منصة ويب عربية لمقارنة أسعار المنتجات، وتجميع تجارب أسعار الخدمات، ومراجعة المساهمات. المشروع يعمل كسيرفر Node.js بدون مكتبات خارجية، ويحتوي على واجهة متجاوبة للكمبيوتر والموبايل.

## ما الذي يعمل الآن؟

- واجهة عربية/إنجليزية فعلية مع تبديل RTL/LTR، وحفظ اللغة المختارة، وترجمة عناصر الواجهة والنصوص الديناميكية والأقسام والمحافظات، مع تنسيق أرقام وتواريخ وعملة حسب اللغة.
- واجهة متجاوبة مع وضع فاتح/داكن وقائمة تنقل سفلية للموبايل.
- بحث عن منتجات عبر مزود أسعار خارجي عند ضبط مفتاحه، مع إظهار العروض حسب المتجر والسعر والبائع والتوفر ووقت الرصد ورابط المصدر.
- بحث مباشر احتياطي في Amazon.eg وNoon وJumia وB.TECH وDubizzle وFacebook Marketplace عند عدم تفعيل مزود الأسعار. هذه روابط بحث خارجية وليست نتائج أسعار مجمعة.
- أقسام منتجات واسعة: الهواتف، الكمبيوتر، الإلكترونيات، الأجهزة المنزلية، الملابس، العناية، البقالة، الأثاث، مستلزمات المنزل، الأطفال، الرياضة، الكتب، السيارات، الحيوانات، وغيرها.
- أقسام خدمات: صيانة الأجهزة، صيانة المنزل، السيارات، التنظيف والنقل، الصالونات، التعليم، التصوير والمناسبات، وغيرها.
- المحافظات المصرية الـ27.
- مقارنة عروض المتاجر، ومقارنة عروض الخدمات مع تجارب معتمدة فقط. لا يصدر النظام حكمًا على سعر خدمة قبل وجود خمس تجارب معتمدة مطابقة على الأقل خلال 180 يومًا.
- إضافة مساهمات الأسعار وإرسالها للمراجعة، وسجل مساهمات المتصفح، واعتماد/رفض من لوحة الإدارة.
- حفظ المنتجات والمفضلة وتنبيهات محلية وسجل البحث ومشاركة روابط بحث قابلة للفتح.
- سجل تاريخي للسعر عندما يرسله مزود البيانات، ونسخة PWA قابلة للتثبيت مع تخزين ملفات الواجهة الأساسية للعمل دون اتصال (طلبات الأسعار تحتاج اتصالًا).
- دعم الرجوع والتقدم عبر أزرار الماوس الجانبية (Back/Forward) وأزرار لوحة المفاتيح Alt + ← / Alt + →.
- تسجيل دخول Google OAuth 2.0 من جهة الخادم باستخدام Authorization Code + PKCE والتحقق من توقيع ID Token عبر مفاتيح Google، وجلسة موقعة في Cookie آمنة. يُستخدم الاسم والبريد والصورة فقط ولا نطلب صلاحية Gmail Inbox.
- بطاقة تسجيل دخول Google ظاهرة في صفحة الحساب، مع حالة إعداد واضحة وزر خروج، وتحديث واجهة الحساب حسب حالة الجلسة.
- API خلفي لحالة الاتصال والبحث والعروض والمتاجر والمساهمات والمقارنة والإدارة وحالة المصادقة وتسجيل الخروج.
- قاعدة بيانات محلية دائمة للتجربة، أو Supabase/PostgreSQL في الاستضافة.

## تشغيل محلي

المتطلبات: Node.js 20 أو أحدث.

```bash
# 1) انسخ ملف الإعدادات
cp .env.example .env

# 2) افتح .env واضبط KAM_ADMIN_TOKEN على قيمة طويلة وعشوائية

# 3) شغّل السيرفر
npm start
```

افتح: `http://localhost:4173`

لا توجد حاجة إلى `npm install`؛ المشروع لا يستخدم حزم NPM خارجية.

## تسجيل الدخول باستخدام Google

تسجيل الدخول يستخدم Google OAuth 2.0 لحساب Google (عنوان Gmail أو أي حساب Google مؤهل). **لا يقرأ الموقع الرسائل أو جهات الاتصال أو ملفات Drive**؛ النطاقات المطلوبة هي `openid email profile` فقط.

للتفعيل:

1. افتح Google Cloud Console وأنشئ OAuth Client ID من نوع **Web application**.
2. أضف Authorized JavaScript origin: `https://YOUR-DOMAIN` (وفي التطوير `http://localhost:4173`).
3. أضف Authorized redirect URI مطابقًا تمامًا لقيمة `GOOGLE_REDIRECT_URI`، مثل `https://YOUR-DOMAIN/auth/google/callback`.
4. انسخ Client ID وClient Secret إلى `.env` على السيرفر فقط.
5. ولّد سر جلسات طويلًا باستخدام `openssl rand -hex 32` وضع الناتج في `KAM_SESSION_SECRET`.
6. اضبط `PUBLIC_BASE_URL` على عنوان الموقع العام مع HTTPS، ثم أعد تشغيل السيرفر.

مثال إعداد:

```env
PUBLIC_BASE_URL=https://YOUR-DOMAIN
GOOGLE_CLIENT_ID=YOUR_GOOGLE_CLIENT_ID
GOOGLE_CLIENT_SECRET=YOUR_GOOGLE_CLIENT_SECRET
GOOGLE_REDIRECT_URI=https://YOUR-DOMAIN/auth/google/callback
KAM_SESSION_SECRET=YOUR_RANDOM_64_HEX_CHAR_SECRET
```

يستخدم الخادم `state` و`nonce` وPKCE، ويتحقق من توقيع Google ID Token و`issuer` و`audience` ووقت الصلاحية والبريد الموثق قبل إنشاء جلسة مدتها 7 أيام. يتم تخزين الجلسة في Cookie تحمل `HttpOnly` و`SameSite=Lax` و`Secure` عند HTTPS. لا تضع مفاتيح Google في `public/` ولا ترفع ملف `.env` إلى GitHub.

عند عدم ضبط المفاتيح أو سر الجلسة، تظهر حالة إعداد غير مكتمل ولا يتم عرض تسجيل الدخول على أنه مفعّل. هذا متوقع في نسخة محلية غير مربوطة بحساب Google.

## تفعيل الأسعار الحية من المتاجر

المشروع يحتوي على موصل server-side لمزود PriceLens:

1. احصل على API key من صفحة المطورين: https://pricelens.store/en/developers
2. أضف المفتاح إلى `.env`:

```env
PRICELENS_API_KEY=ضع_المفتاح_هنا
PRICELENS_BASE_URL=https://pricelens.store/api/v1/partner
```

3. أعد تشغيل السيرفر.

الموصل يستخدم `/search` للعثور على المنتجات، ثم `/products/{id}/market` لجلب عروض المتاجر، ويستخدم `/deals` للعروض و`/stores` لقائمة المتاجر. تغطية المتاجر تعتمد على ما يرجعه المزود في خطتك ووقت البحث؛ لا نفترض أن كل متجر متاح لكل منتج.

**مهم:** مفتاح API يظل على السيرفر ولا يوضع داخل `public/app.js`. تعرض الواجهة رابط العرض كما يرده المزود، وتضيف نسبة المصدر `Prices by PriceLens` وفق شروطه. لا تعِد نشر بيانات المزود الخام كواجهة API منافسة.

### Amazon وNoon وDubizzle

- Amazon.eg وNoon وغيرهما يظهرون ضمن عروض PriceLens عندما تكون منتجاتهم مغطاة في استجابته.
- Amazon توفر Creators API لسوق مصر، لكن الوصول يتطلب التسجيل في Associates ثم التسجيل في Creators API والحصول على مفاتيح وصول. هذا الإصدار يستخدم مجمّع الأسعار ولا يحتوي بعد على موصل مباشر مستقل لـ Amazon Creators API.
- رابط Noon الظاهر كبحث مباشر لا يعني أن Noon متصل حيًا. تكاملات البائعين الخاصة بـ Noon ليست بديلًا تلقائيًا عن واجهة أسعار استهلاكية عامة.
- Dubizzle منصة إعلانات مبوبة/مستعمل؛ الإصدار الحالي يفتح بحثًا خارجيًا فقط ولا يستخرج إعلانات أو أسعارًا آليًا. لا توجد موصلات غير معتمدة أو تجاوزات لحماية المواقع.

## قاعدة البيانات المشتركة (Supabase)

بدون Supabase، يحفظ السيرفر البيانات في `data/kam-data.json`؛ هذا مناسب لتجربة محلية أو سيرفر واحد بقرص دائم، وليس لتشغيل عدة نسخ متوازية.

لبيئة مشتركة:

1. أنشئ مشروع Supabase.
2. شغّل محتويات `migrations/001_initial.sql` من SQL Editor.
3. أضف إلى `.env`:

```env
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY
```

4. أعد تشغيل KAM.

مفتاح `service_role` سري بالكامل ويظل في السيرفر. الجداول تستخدم RLS دون سياسات وصول عامة؛ عمليات قاعدة البيانات تمر عبر الخلفية فقط. عند تسجيل الدخول عبر Google، يربط الخادم المساهمات بمعرّف Google الثابت بدل معرّف المتصفح. الضيوف يظلون على معرّف متصفح محلي؛ سجلات الضيف السابقة لا تُنقل تلقائيًا لحساب Google.

## إعداد لوحة الإدارة

أضف رمزًا قويًا في `.env`:

```env
KAM_ADMIN_TOKEN=قيمة_طويلة_وعشوائية_جدا
```

افتح `http://localhost:4173/#admin` ثم أدخل الرمز. لا تضع الرمز داخل ملفات الواجهة أو GitHub.

## واجهات API

| Method | Endpoint | الوظيفة |
|---|---|---|
| GET | `/api/auth/me` | حالة جلسة Google والمستخدم الحالي |
| GET | `/auth/google` | بدء تسجيل الدخول باستخدام Google |
| GET | `/auth/google/callback` | استقبال نتيجة OAuth والتحقق من الهوية |
| POST | `/auth/logout` | إنهاء جلسة Google |

| Method | Endpoint | الوظيفة |
|---|---|---|
| GET | `/api/health` | حالة السيرفر والتكاملات |
| GET | `/api/config` | المحافظات والتصنيفات والمتاجر |
| GET | `/api/market/search?q=` | بحث أسعار المنتجات |
| GET | `/api/market/deals` | العروض ذات التخفيض الموثق من المزود |
| GET | `/api/market/stores` | قائمة المتاجر من المزود |
| GET | `/api/contributions` | التجارب المعتمدة |
| GET | `/api/contributions?mine=1` | مساهمات معرّف المتصفح الحالي |
| POST | `/api/contributions` | إضافة مساهمة للمراجعة |
| POST | `/api/compare/service` أو `/api/compare/contributions` | مقارنة سعر خدمة أو منتج ببيانات مجتمع معتمدة |
| GET | `/api/admin/queue` | قائمة المراجعة (تحتاج Bearer admin token) |
| PATCH | `/api/admin/contributions/:id` | اعتماد أو رفض مساهمة (تحتاج Bearer admin token) |

## نشر على Render باستخدام Docker

- اربط المستودع بـ Render واختر Docker.
- اضبط `PUBLIC_BASE_URL` بعنوان HTTPS المنشور، و`GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` و`GOOGLE_REDIRECT_URI` و`KAM_SESSION_SECRET` لتفعيل Google Sign-In.
- أضف `PRICELENS_API_KEY` و`KAM_ADMIN_TOKEN` وبيانات Supabase إن استخدمتها.
- يجب أن يطابق عنوان Google callback في Google Cloud Console قيمة `GOOGLE_REDIRECT_URI` حرفيًا.
- استخدم `/api/health` كـ Health Check.
- إذا لم تستخدم Supabase، أضف Persistent Disk عند `/app/data` حتى لا تضيع مساهمات JSON عند إعادة النشر.

## ما الذي لا يزال يحتاج استكمالًا قبل إطلاق تجاري عام؟

- تفعيل مفاتيح مزود الأسعار والاتفاق على خطة البيانات المناسبة.
- استكمال سياسة خصوصية وشروط استخدام ومراجعة قانونية قبل الإطلاق التجاري العام، وتحديد مدد الاحتفاظ ببيانات الحسابات.
- رفع إيصالات آمن مع إخفاء البيانات الحساسة ومراجعة الملفات.
- تنبيهات أسعار تعمل في الخلفية عبر Queue/cron وبريد أو Push؛ التنبيهات الحالية محلية وتتحقق عند البحث والمصدر متصل.
- موصل مباشر مع Dubizzle يتطلب اتفاقًا أو تغذية بيانات معتمدة.
- اختبارات أمنية، سياسة خصوصية وشروط استخدام، مراقبة أخطاء ونسخ احتياطي قبل استقبال بيانات المستخدمين على نطاق واسع.
